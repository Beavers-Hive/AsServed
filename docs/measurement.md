# 実寸投影と距離測定のしくみ

このプロジェクトの主張は「机の上のものが**実寸**である」ことです。その根拠を、
座標系・較正・測定・誤差要因の順にまとめます。実装は `src/geometry.py`、`src/render.py`、
`src/pointer.py`、`src/pinch_distance.py` に対応します。

## 1. 座標系は3つ、変換はホモグラフィ1枚

扱う点はすべて**机の天板という1枚の平面上**にあります。同一平面上の点どうしなら、
どの視点から見た像も 3x3 ホモグラフィ1枚で相互変換できます（`src/geometry.py`）。

```
  cam(px)  ──H_cam→proj──▶  proj(px)          calibration.json（4隅クリック）
  table(mm)──H_table→proj─▶  proj(px)          metric.json（較正ボード）
  cam(px)  ──H_cam→table──▶  table(mm)         上2つから導出: inv(H_table→proj) @ H_cam→proj
```

- **cam** … カメラ画像のピクセル
- **proj** … プロジェクターのフレームバッファのピクセル
- **table** … 机の平面のミリメートル。原点と向きは較正ボードが決める

描画は最初から最後まで mm で行い、`render.py` の内側でだけ proj px へ落とします。
実寸を主張する以上、途中で px に落とすと根拠が追えなくなるためです。

> **1mm = N px という単一の倍率は存在しません。** 机を斜めから投影するので遠近がつき、
> 倍率は場所ごとに変わります。必ず点ごとにホモグラフィで変換します。
> `TableFrame.px_per_mm_at()` は局所的な目安で、診断表示専用です。

## 2. 投影のしくみ

`render.py` は「mm で指定された図形」を投影面へ描きます。

| 関数 | 用途 |
|---|---|
| `draw_polyline_mm` / `fill_poly_mm` | 線・塗り。頂点を mm で渡す |
| `draw_plate_mm` | 皿の輪郭（実寸の円）。`dashes>0` で破線＝まだ置かれていない皿 |
| `draw_image_mm` | 料理写真を「幅 width_mm の実物」として置く（4隅を mm で決めて透視変換） |
| `draw_text_mm` | 高さ height_mm の文字。斜め投影でも机の上で指定した高さになる |

円や画像も、頂点を mm で作ってから一括で変換します。こうすると台形歪みが自動的に
かかり、机の上では正しい形・正しい寸法に見えます。

投影範囲は `TableFrame.projection_bounds_mm()` がプロジェクターの4隅を机の mm へ
引き戻して求めます。斜め投影なので実際に光が届くのは台形で、UI の自動配置には
その**内接**矩形を使います（外接矩形だと角が欠ける）。

## 3. 較正の3段階

| 手順 | スクリプト | 生成物 | 中身 |
|---|---|---|---|
| 1 | `src/calibrate.py` | `calibration.json` | H_cam→proj。投影した基準矩形の4隅をカメラ映像上でクリック |
| 2 | `src/make_board.py` | `markers/*.pdf` | ArUco 較正ボード。実寸で印刷する（「用紙に合わせる」は切る） |
| 3 | `src/calibrate_metric.py` | `metric.json` | H_table_mm→proj。ボード6枚 24点の最小二乗 |
| 4 | `src/calibrate_metric.py --verify` | — | 100mm グリッドと直径220mm の円を投影。定規で確認 |

較正の質は **残差 RMS を mm で** 出します（`metric.json` の `residual_rms_mm`）。
proj px ではなく mm へ引き戻して評価するので、そのまま実寸精度の指標になります。
現在のこのリポジトリの値は **0.72 mm**（目安は 2mm 以下）。

較正後にカメラかプロジェクターを動かしたら、手順1からやり直しです。

## 4. 距離測定（親指と人差し指の先端）

`src/pinch_distance.py`。同じ計測から**意味の違う2つの距離**を常に計算し、
`--source` はどちらを主表示にするかだけを決めます。

| | world（既定） | table |
|---|---|---|
| 元データ | `hand_world_landmarks`（手の中心が原点のメートル座標） | 指先の px をホモグラフィで机平面へ |
| **較正** | **使わない** | **使う**（calibration.json + metric.json） |
| 前提 | なし（浮いていても測れる） | 指が机に触れていること |
| 弱点 | モデルのスケール推定・z 推定の誤差 | 視差、机平面への射影で縮む、レンズ歪み |

**「較正しているのに値がおかしい」と思ったら、まず主表示がどちらかを確認してください。**
既定の world は較正を一切通りません。補助行に world / table の両方を出しているのは、
このためです。

補助行の読み方:

```
world 61.2mm | table 20.4mm | 95px | scale 94.8mm | tilt 70deg | Right
```

| 項目 | 意味 |
|---|---|
| `world` / `table` | 上表の2系統。丸めも不感帯もかけない生の値 |
| `px` | カメラ画像上の指先間ピクセル |
| `scale` | 手首(0)→中指の付け根(9)。開閉しても変わらない**はず**の剛体長 |
| `tilt` | つまみ軸が画像平面から何度傾いているか。0度=真横、90度=カメラ正面 |
| `Left`/`Right` | MediaPipe が判定した手 |

## 5. 値を落ち着かせるしくみ

指を止めていてもランドマークのノイズで数 mm 揺れます。一方でつまむ動作は速い。
固定係数の EMA では両立できない（弱いと震え、強いと追従しない）ので2段構えです。

1. **1€ フィルタ**（`--filter euro`、既定）— 推定速度に応じてカットオフを上げる。
   静止時だけ強く均すので、ちらつきを追従性と引き換えにしない。
   `--min-cutoff` を下げるほど静か、`--beta` を上げるほど機敏。
2. **表示側の丸めと不感帯**（`--step-mm 1` / `--deadband-mm 1.5`）— 下位桁の往復を
   止めるのはフィルタではなくこちらの仕事。線の描画とつまみ判定には連続値を使い続ける。
   不感帯は丸め幅の半分より大きくすること（等しいと境目で往復する）。

30fps・生のσ≈1.8mm でのシミュレーション結果:

| | 静止時の表示変化 | つまみ(70→20mm/0.3s)の追従 |
|---|---|---|
| 固定EMA(α=0.45) + 0.1mm 表示 | 28.8 回/秒 | 100 ms |
| 1€ + 1mm 刻み / 1.5mm 不感帯 | **0.6 回/秒** | **67 ms** |

数字が止まるだけでなく追従も速くなります（速い動きではカットオフが上がるため）。

つまみ判定（`PinchGate`）はヒステリシス付きで、閉じる閾値 30mm に対し開くのは 1.35倍。
境目での反転を防ぎます。

## 6. 誤差要因（効く順）

### 6-1. つまみ軸の向き — 最大の要因

手首が回って親指と人差し指が「上下」に並ぶと、開き具合が同じでも数値が大きく縮みます。

- **table** は机平面への射影長なので、`cos(傾き)` 倍そのもの
- **world** は3次元距離だが、傾くほど距離の大半を MediaPipe の最も苦手な z 成分が担う

| 傾き | 射影の縮み |
|---|---|
| 0度（真横から見える） | 1.00 |
| 45度 | 0.71 |
| 60度 | 0.50 |
| **70度** | **0.34** |

実際に「机の右で 60mm、左で 20mm」という食い違いが出た事例は、この 70度に一致しました
（視差でもスケール揺れでも説明がつかない大きさ）。45度を超えると画面に警告を出します。
**左右どちらで測るときも手の向きを揃えてください。**

### 6-2. モデルのスケール推定の揺れ

`scale`（手首→中指付け根）は本来一定です。これが動くならモデルの推定スケールが
揺れているということで、つまみ幅も同じ比率でずれます。定規で自分の手のその長さを
実測して渡すと、比で毎フレーム打ち消せます。効くのは1〜2割の差までです。

```bash
uv run python src/pinch_distance.py --ref-mm 95
```

### 6-3. 視差（table のみ）

ホモグラフィは机の平面上の点にしか使えないので、指が浮くとずれます。ただし
**このずれは思ったほど大きくなく、左右差もほとんど出ません**。較正値からカメラ姿勢を
復元して計算した結果（焦点距離は 800〜1200px を仮定。カメラ高さ ≈ 320mm）:

| 実寸 60mm の開き | 0mm 浮き | 30mm | 60mm | 100mm |
|---|---|---|---|---|
| 机の中央 | 60 | 66 | 74 | 88 |
| 机の右寄り | 60 | 66 | 74 | 88 |

**増える**方向で、最大でも1.5倍程度。数倍の食い違いを視差のせいにしないでください。
指差し UI（`table_sign.py`）では「机に触れて指す」前提と大きな的（最低70mm角）で
この誤差を設計的に潰しています。

### 6-4. 場所による局所倍率の違い（table のみ）

平面上の点でも、mm/px は画面内で大きく変わります（斜め視のため。これ自体は正しい挙動）。

| カメラ画像の位置 | 60px の開き → | mm/px |
|---|---|---|
| 左端 中央 | 57.4 mm | 0.96 |
| 右端 中央 | 51.5 mm | 0.86 |
| 左上（奥） | 178.7 mm | 2.98 |
| 右下（手前） | 31.9 mm | 0.53 |

机平面の消失線は画像のすぐ上（y ≈ -7 〜 -33 px）にあり、画像上部ほど mm が発散します。
**画面の上のほうでは table 値を信用しないでください。**

### 6-5. レンズ歪み（未対応）

このリポジトリは歪み補正を一切していません（`cameraMatrix` / `undistort` の使用箇所ゼロ）。
広角カメラでは画面端で追加のずれが出ます。必要になったらチェッカーボードで内部パラメータを
取り、ホモグラフィを当てる前に undistort する工程を挟むことになります。

## 7. 原因の切り分け手順

1. 補助行の `[world]` / `[table]` で、いま見ている数字がどちらか確認する
2. `tilt` を見る。45度以上なら**まず手の向きを直す**（他の調整をしても無駄）
3. `scale` を左右で見比べる。動くなら `--ref-mm` で正規化する
4. それでも合わないなら記録して比較する

```bash
uv run python src/pinch_distance.py --log out.csv
```

CSV は1フレーム1行で `t, handedness, cam_x, cam_y, world_mm, table_mm, px, hand_scale_mm, tilt_deg`。
左で数秒、右で数秒つまんで記録すれば、位置・持ち手・向きのどれが効いているかを数字で判定できます。

## 8. パラメータ一覧

`config.json` の `pinch` セクション（CLI 引数のほうが優先）。

| キー | 既定 | 意味 |
|---|---|---|
| `filter` | `euro` | `euro` = 1€ フィルタ / `ema` = 固定係数 / `none` = 生の値 |
| `min_cutoff` | 0.7 | 1€: 静止時のカットオフ Hz。下げるほど静か |
| `beta` | 0.015 | 1€: 速い動きへの追従。上げるほど機敏 |
| `step_mm` | 1.0 | 表示の丸め幅。0 で丸めない |
| `deadband_mm` | 1.5 | この量動くまで表示を書き換えない |
| `pinch_mm` | 30.0 | 「つまんだ」と見なす距離 |
| `ref_mm` | `null` | 手首→中指付け根の実測 mm。スケール正規化に使う |

主なコマンド:

```bash
uv run python src/pinch_distance.py                 # カメラ映像に重ねて表示
uv run python src/pinch_distance.py --source table  # 机 mm を主にする
uv run python src/pinch_distance.py --project       # 机に投影して表示（要較正）
uv run python src/pinch_distance.py --check         # 機材を開かずに設定だけ確認
uv run python src/pinch_distance.py --min-cutoff 0.4              # もっと静かに
uv run python src/pinch_distance.py --filter none --step-mm 0 --deadband-mm 0   # 素の値
```

キー操作: `s` 主表示の切り替え / `e` 言語 / `d` デバッグ表示 / `ESC`・`q` 終了。

## 9. 対応するファイル

| ファイル | 役割 |
|---|---|
| `src/geometry.py` | 3つの座標系とホモグラフィ、投影範囲、残差計算 |
| `src/render.py` | mm で図形と文字を描く（透視補正込み） |
| `src/pointer.py` | 人差し指の先端を追い、机の mm へ落とす（指差し入力） |
| `src/pinch_distance.py` | 親指と人差し指の距離。2系統の測定・平滑化・診断 |
| `src/calibrate.py` / `src/calibrate_metric.py` | 較正 |
| `tests/test_geometry.py` / `tests/test_pinch_distance.py` | 機材なしで通る自動テスト |

計算・フィルタ・診断のロジックはすべて機材なしのテストで固めてあります。実機で疑うのは
「認識」と「較正」だけで済む状態を保つためです。

```bash
uv run pytest tests -q
```
