# As Served — 実寸で見せる卓上メニューサイン（日本語の詳細手順）

> 英語の概要とプロジェクト紹介は **[../README.md](../README.md)** にあります。
> このファイルは較正・運用・設定の詳細をまとめた作業手順書です。

**注文する前に、実際に出てくる量そのままの大きさで料理が机に現れる。**

超短焦点プロジェクターが机に料理を **実寸（1:1）** で投影します。料理とサイズは
机に映ったメニューを **指で3秒指すだけ**で選べます（机に触れるだけ、タッチパネル不要）。
S / M / L は皿の輪郭を重ねて実寸で比較できます。注文を確定すると、SO-101
ロボットアームが料理に合わせて**本物のフォークまたは箸**を客席へ運びます。

Seeed Studio *Make a Sign — Interactive Signage Contest 2026* 応募プロジェクト。

## 何を解決するのか

飲食店のメニュー写真は「量」が分からない。結果として

- 頼みすぎて残す（店にとっては原価の損失、環境負荷）
- 足りなくて追加注文（回転率の低下）
- 外国人客・初来店客が量を読めず、注文をためらう

写真をきれいにしても解決しません。**寸法の情報が欠けている**のが原因だからです。
このサインは料理を実寸で机に置いて見せることで、量の判断を「読む」から「見る」に変えます。

## 2層構成（重要）

このプロジェクトは意図的に2つの階層に分けてあります。

| | 構成 | できること | 概算コスト |
|---|---|---|---|
| **Tier 1** | 超短焦点プロジェクター + Mac/RasPi + XIAO + USBカメラ | 実寸投影、指差し選択、S/M/L 比較、多言語、アレルゲン表示 | 数万円 |
| **Tier 2** | Tier 1 + SO-101 アーム | 注文した料理に合うフォーク／箸が届く | + アーム |

**Tier 1 だけで製品として成立します。** アームは体験を完成させる追加レイヤーであって、
必須部品ではありません。`src/table_sign.py` は実行時にアームもカメラも要求しません。

## セットアップ

Python は **uv** で管理します。

```bash
uv venv --python 3.12 .venv
uv pip install -r requirements.txt
```

## 較正（実寸の根拠をつくる工程）

「実寸である」という主張は較正の質そのものです。3ステップで、最後に定規で検証します。

### 0. 投影先とカメラを確認する

```bash
uv run python src/list_displays.py --test
```

各ディスプレイに番号が順に表示されます。**プロジェクターに出た番号**を
`config.json` の `projector.display_index` に、**そのディスプレイの解像度**を
`projector.width` / `height` に設定してください。解像度が違うと較正が根本的に狂います。

1台しか検出されない場合はミラーリングになっています。システム設定 > ディスプレイ で
「ディスプレイを拡張」にしてください。

### 1. カメラ → プロジェクターの対応をとる

```bash
uv run python src/list_cameras.py
```

表示された `uid` または `name` を `config.json` の `camera.uid` / `camera.name` に設定してから、

```bash
uv run python src/calibrate.py
```

プロジェクターに基準矩形が出るので、カメラ映像上で投影の4隅を
左上 → 右上 → 右下 → 左下 の順にクリックし `s` で保存 → `calibration.json` ができます。

**以後、カメラとプロジェクターは動かさないでください。** 動かしたらここからやり直しです。

うまくいかないときのオプション:

```bash
uv run python src/calibrate.py --display 0        # 投影先を一時的に変える
uv run python src/calibrate.py --auto-exposure    # カメラ映像が暗すぎるとき
uv run python src/calibrate.py --mode fullscreen  # 投影方式を切り替える
```

**投影が一瞬映って消える場合**は macOS のフルスクリーン挙動です。SDL は真のフルスクリーンの
ウィンドウがフォーカスを失うと最小化し、macOS はさらに専用 Space を作るため、操作用の
OpenCV ウィンドウをクリックした瞬間に投影が引っ込みます。既定の
`projector.mode: "borderless"`（デスクトップと同じ大きさの枠なしウィンドウで
ディスプレイを覆う）ならこれが起きません。

**カメラ映像が真っ暗な場合**は `config.json` の `camera.auto_exposure` を確認してください。
`false` にすると `exposure` / `gain` の値で固定しようとしますが、
`AVCaptureExposureModeCustom` に対応していないカメラでは**起動時の露出のまま
ロックされるだけ**で、暗い部屋では真っ暗になります（ログに
`[avf_camera] 露出をロックしました。` と出ていたらこれ）。既定は `true`（自動）です。

### 2. 較正ボードを印刷する

```bash
uv run python src/make_board.py
```

**印刷には PDF を使ってください。**
`markers/board_DICT_4X4_50_60mm_90mm_a4_landscape.pdf` が生成されます。
A4横のページにボードが実寸で配置済みなので、**「実際のサイズ」で印刷するだけ**です。

PDF はページの物理サイズを絶対値で持つので、アプリごとの DPI 解釈に左右されません。
PNG を直接印刷すると、DPI を 72 と解釈するアプリ（macOS のプレビューなど）では
**約4.2倍に拡大**されます（PNG 側にも 300dpi を埋めてありますが、PDF のほうが確実です）。

**「用紙に合わせる」は必ず切ってください。** 有効だと数%縮み、その分そのまま投影がずれます。
これが寸法較正で一番よくある失敗です。

印刷したら、**ページ下部の 100mm の物差しを定規で測ってください。** ちょうど 100.0mm なら
スケールは正しく、ずれていれば印刷時に拡大縮小がかかっています。

A4 縦でしか印刷できない場合は、縦に収まるボードを作れます（マーカーが小さくなる分、
遠くへ外挿したときの精度は落ちます）。

```bash
uv run python src/make_board.py --cols 2 --rows 3 --marker-mm 50 --pitch-mm 75
```

`--paper a3` `--paper letter` `--paper b5` も指定できます。実寸で載るかを判定し、
入らない場合は縮小案を提示します。

印刷したら **定規でマーカー1辺（黒枠込み）を実測**してください。プリンタは
たいてい 1〜2% 縮みます。これを補正しないと投影が同じだけ小さくなります。

### ボードを置く位置

較正は、置いたボードから外へ**外挿**するほど誤差が増えます。**実際に料理を投影する
あたり（提供位置）にボードを置いて**較正してください。そこが一番精度の要る場所です。

### 3. mm → プロジェクターの対応をとる

ボードを机の、料理を出すあたりに平らに置いて（投影は消した状態が確実です）:

```bash
# 印刷が公称どおり 60mm だった場合
uv run python src/calibrate_metric.py

# 実測が 58.6mm だった場合
uv run python src/calibrate_metric.py --measured-marker-mm 58.6
```

`metric.json` が生成され、**残差 RMS が mm で表示されます**。2mm 以下を目安にしてください。

### 4. 定規で検証する

```bash
uv run python src/calibrate_metric.py --verify
```

100mm グリッド・100mm スケールバー・直径220mm の円が投影されます。定規を当てて
一致することを確認してください。手持ちの 22cm 皿を円に重ねるのが一番速い確認方法です。
**この検証カットは応募動画にそのまま使えます**（実寸であることの証拠になる）。

## 指差しで選ぶ

MediaPipe で人差し指の先端を追い、既存の較正（cam → table）で机の mm 座標へ落として、
投影されたメニューとの当たり判定をとります。同じ的を **3秒**指し続けると確定し、
的の外周が伸びて残り時間を示します。

MediaPipe 1.0 で旧 API が廃止され、モデルファイルが外部配布になりました。
ライセンスと容量の都合でリポジトリには同梱していません。一度だけ取得してください
（約 7.5MB、Google 公式配布、Apache-2.0）。

```bash
uv run python src/fetch_model.py
```

### 机に触れて指すこと

ホモグラフィは「点が机の平面上にある」前提の変換です。**指が机から浮いていると、
その分だけ指した先がずれます**（50mm 浮くと数十 mm ずれることもあります）。

対策は3つ入れてあります。

1. **机に触れて指す前提のUI。** 触れていれば指先は本当に平面上にあり、視差はゼロ
2. **的を大きく**（最低 70mm 角。`ui.MIN_TARGET_MM`）
3. **指先の照準を投影して返す。** 自分の指がどう認識されているか見えれば人は勝手に直します

それでも系統的にずれる場合は `config.json` の `pointer.offset_mm` で一定量ずらせます。
`d` キーでポインタ座標と認識 FPS を表示できます。

### 指の距離を測る

親指と人差し指の先端の距離を実寸で表示する道具も入っています（つまみ幅を入力に使う
機能の土台。単体で動きます）。

```bash
uv run python src/pinch_distance.py            # カメラ映像に重ねて表示
uv run python src/pinch_distance.py --project  # 机に投影して表示（要較正）
```

座標系・較正・平滑化・誤差要因（指の向き / スケール推定 / 視差 / 局所倍率）は
**[docs/measurement.md](measurement.md)** にまとめてあります。値が場所によって
変わる、数字が暴れる、といったときはそちらを参照してください。

## 実行

```bash
uv run python src/table_sign.py --pointer hand              # 指差しで選ぶ
uv run python src/table_sign.py                             # キーボードのみ
uv run python src/table_sign.py --pointer scripted          # 擬似ポインタで挙動確認
uv run python src/table_sign.py --arm mock --pointer hand   # アームの指示はログで確認
uv run python src/table_sign.py --arm serial --arm-port /dev/cu.usbmodem1101
uv run python src/table_sign.py --lang ja                   # 日本語表示で起動
```

**表示は既定で英語です**（コンテストの審査員・投票者に合わせています）。`config.json` の
`table_sign.language` を `"ja"` にするか `--lang ja` で日本語にでき、実行中は `e` キーで
いつでも切り替わります。

キーボードは指差しと併用できます（撮影時のフォールバック用に残してあります）。
投影ウィンドウにフォーカスを当てて操作します。

| キー | 動作 |
|---|---|
| `←` `→` | 料理を切り替え |
| `↑` `↓` / `1` `2` `3` | サイズ S / M / L |
| `ENTER` | 注文する |
| `s` | カット数（4 / 6 / 8） |
| `c` | 他サイズの比較リング |
| `r` | 100mm スケールバー（実寸の証拠） |
| `g` | アレルゲン表示 |
| `e` | English / 日本語 |
| `d` | デバッグ表示（ポインタ座標・FPS） |
| `ESC` | 終了 |

### ピザカッター（カット数）

ピザは **4 / 6 / 8 カット**を選べます。選ぶと実寸のピザの上に実寸でカット線が刻まれるので、
「1切れがどのくらいか」もそのまま分かります。カット数の脇に **1切れの重さ**が出るので、
サイズを上げれば同じカット数でも1切れが大きくなることが数字で見えます。

**この機能は主役ではありません。** サイズ選択が主役のままになるよう、序列を作ってあります。

| | サイズ | カット数 |
|---|---|---|
| 的の大きさ | φ92mm | φ72mm |
| 位置 | 一番外側（手が自然に伸びる先） | その内側 |
| 選択中の色 | アンバー（このUIで唯一） | グレー |
| 見出し | `SIZE` 13mm | `SLICES` 8.5mm |

的の大きさの逆転は `tests/test_ui_pointer.py` で検査しているので、うっかり崩れません。
カット線もサイズ比較のリングより細く薄くしてあります。

カットできる料理だけ `menu.json` に `"slice_options": [4, 6, 8]` を書きます。
書かなければカット UI もカット線も出ません（パスタなどはこれで素通りします）。

投影範囲が狭くてカット列を置けない場合は、カット UI を出さずサイズ選択の見やすさを
優先します（`s` キーでは操作できます）。

### 注文完了の表示

注文が確定すると、**投影面いっぱいがアンバーに塗りつぶされ**、チェックマークと
注文内容が大きく出ます（`ORDER PLACED` / 料理名・サイズ・価格・重量・kcal）。
机の上では黒＝光を出さない状態なので、面を明るく塗ると「机全体が反応した」ように見えます。
文字は塗りの上に暗色で置く＝そこだけ光を抜く、という作りです。

中心から円が広がる演出（約0.45秒）のあと6秒保持し、下部の残り時間バーが尽きると
メニューへ戻ります。`ORDER_HOLD_S` で変更できます。

### 必要な投影範囲

実寸の料理とメニューを同時に出すので、投影範囲が広いほど大きいサイズを扱えます。
同梱メニュー（S 220 / M 270 / L 320mm のピザ、皿は +35mm）は **750 × 390mm** の投影で収まります。

ここでいう投影範囲は、台形に**内接**する矩形です（`--check` が表示する値）。斜め投影なので
実際に光が届くのは台形で、その外接矩形で考えると角の付近が欠けます。UI の自動配置は
内接矩形を使うので、上端の文字が切れるといったことは起きません。

狭い場合は料理名とスペックを自動的に皿のふちの内側へ回し、注文ボタンも実寸プレビューを
避けた位置へ移します。ただし**料理そのものは実寸から縮められません**（縮めたら作品の
意味がなくなるため）。`--check` が投影範囲を実測値で表示し、収まらない場合は警告するので、
プロジェクターを離すか `menu.json` のサイズを見直してください。

機材が無い状態での確認:

```bash
uv run python src/table_sign.py --check                 # 設定・素材・較正の状態を点検
uv run python src/table_sign.py --preview out.png       # 1フレームを PNG に書き出す
uv run pytest tests -q                                  # 機材なしで通る自動テスト
```

## メニューを増やす

`menu.json` を編集します。寸法は mm、重量は g。

```json
{"label": "M", "served_g": 400, "kcal": 1080, "price_yen": 1580,
 "plate_diameter_mm": 285, "food_diameter_mm": 250}
```

`food_diameter_mm` が **実寸表示の根拠**です。ピザなら生地の直径そのもの。
麺類の場合は `"dry_g": 110` を足すと、スペック行が直径ではなく乾麺の量になります。
`"utensil": "fork"` または `"utensil": "chopsticks"` で、注文確定後にアームが
運ぶ食器を指定します。メニューやサイズを選んでいる間は動かず、注文時にだけ指示を送ります。

`uv run python src/table_sign.py --check` が矛盾（料理の径が皿より大きい、
最大の皿が投影範囲に収まらない等）を検出します。

### 料理画像を用意する

**画像の幅 = `food_diameter_mm`** として投影されます。料理のまわりに余白が残っていると
その分だけ小さく投影され、実寸の主張が静かに崩れます。切り詰めは必ず専用スクリプトで
行ってください。

```bash
uv run python src/prepare_dish_image.py assets/dishes/_raw/margherita.png \
    -o assets/dishes/pizza_margherita.png --contact-sheet /tmp/check.png
```

背景（四隅の色から推定）を透過にし、最大の連結成分の外接矩形で切り詰め、正方形に整えます。
`--contact-sheet` はアルファの抜け具合を確認するための合成画像です。

同梱の素材（`assets/dishes/pizza_*.png`）は生成画像を真上視点・白背景で作り、
このスクリプトで処理したものです。元画像は `assets/dishes/_raw/` にあります。

**実店舗で使うなら、実際の料理を三脚で真上から撮り、定規で直径を実測して
`food_diameter_mm` に入れてください。** それが「実寸」を名乗る唯一の根拠です。

### 設計の要点

- **描画は全部 mm。** px を触るのは `render.py` の内側だけ。実寸を主張する以上、
  座標系を途中で px に落とすと根拠が追えなくなる。
- **遠近は毎回ホモグラフィで処理する。** 机を斜めから投影するので「1mm = N px」という
  単一の倍率は存在しない。`px_per_mm_at()` は診断表示専用。
- **入力は差し替え可能。** `pointer.py` は「机の mm 座標」だけを返す薄い層。指差し
  （`hand`）、擬似ポインタ（`scripted`）、無し（`none`）を切り替えても、UI 側のコードは
  一切変わらない。撮影中に認識が不調でもキーボードへ即座に逃げられる。
- **UI の配置は投影範囲から自動で決まる。** `TableFrame.projection_bounds_mm()` が
  プロジェクター4隅を机の mm へ引き戻すので、机の広さや設置距離を設定に手で書かなくてよい。
- **アームは疎結合。** ホストは「フォークか箸か」だけを送り、軌道はアーム側に閉じる。
  アームが無くても、壊れても、投影は止まらない。
- **合成はワープ先の外接矩形だけを処理する。** 1フレームに十数個の要素を透視変換するので、
  毎回フル解像度でワープすると数fpsまで落ちる。現状 1920x1080 で約 4.4ms/フレーム。

## 出典

投影パイプライン（ArUco 追従、4隅ホモグラフィ較正、pygame 全画面出力）は
別プロジェクト `projection/` で開発したものを取り込み、mm 座標系と寸法較正を追加しています。
